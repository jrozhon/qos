# Lecture decks — 440-2216/01 Quality of Service

[Slidev](https://sli.dev) decks for the QoS/QoE course, one file per lecture. They share one Slidev project:
the VŠB-TUO layouts, components, fonts, logos and `style.css` live here once, and every deck is a single
Markdown file at the project root.

| `02-queuing-theory.md` | Kendall's notation, the Poisson process, Little's law, the M/M/1 queue, and the Erlang traffic formulas | `qos-02` |

Decks are numbered like the lectures; add `07-…md`, … alongside.

## Run a deck

```bash
cd slides
npm install                                    # once
npm run dev -- 01-information-theory.md        # opens http://localhost:3030
```

Press `d` for dark mode, `o` for the slide overview, `p` for presenter mode (speaker notes are in the `<!-- -->`
blocks at the end of each slide).

## Export

```bash
npm run build  -- 01-information-theory.md     # static site in dist/
npm run export -- 01-information-theory.md     # PDF; needs: npx playwright install chromium
npm run export-notes -- 01-information-theory.md
```

`export` writes `<exportFilename>.pdf` from the deck's frontmatter. One page per slide with all click content
revealed; pass `--with-clicks` for one page per click.

## Writing a new deck

Copy the frontmatter of `01-information-theory.md` (theme, fonts, `mdc`, `exportFilename`) and follow the same
rhythm: cover → outline → thesis `statement` → `section` divider per part → content → summary → lab preview →
references → `end`. Conventions that keep the decks consistent:

- **Layouts** available in frontmatter: `cover`, `default`, `center`, `section`, `statement`, `end`.
- **Checkpoints** — a `.checkpoint-question`, the muted "Predict first · discuss with a neighbour · then reveal"
  line, and a `.checkpoint-answer` with `v-click`. Give students 30 s to think and 30 s to discuss before revealing.
- **Speaker notes** on every slide, naming the lab step or README question the slide serves.
- **Figures** are editable SVGs in `public/figures/<deck>/`, generated by `scripts/generate-figures.py`
  (standard library only; each deck has its own section in the script). They embed Carlito, carry a title and a
  description, and render at native size — 880 px wide for a full-width figure. Embed them with
  `<Figure src="/figures/04/pareto-ccdf.svg" alt="…" />` (not a bare `<img>`): the script writes every figure in a
  light (`name.svg`) and a dark (`name.dark.svg`) variant, and `components/Figure.vue` shows the one matching the
  deck's colour scheme. Take every colour from `PALETTES` in the script, never a literal hex value, or the dark
  variant keeps a light-mode colour (VSB-STYLE.md R7a). Regenerate after editing:

  ```bash
  python3 scripts/generate-figures.py          # both variants
  ```

  State diagrams are the exception: deck 04's loss models are Vue components drawn in the slide itself —
  `GilbertSim` in `diagram` mode for the two-state models (the same drawing its live slides animate) and
  `FourStateDiagram` for the four-state model — so the static and animated versions share one look.

- **Audio samples** live in `public/audio/<deck>/` and are played with `<AudioClip src="/audio/05/…wav" label="…" />`,
  a compact play/stop button that stops any other clip when it starts. Players work in `npm run dev` and the
  built site; the PDF export shows the buttons but cannot play them. Deck 05's codec samples are generated by
  `scripts/generate-codec-samples.py` (needs curl, ffmpeg, a C compiler and the bcg729 library):

  ```bash
  python3 scripts/generate-codec-samples.py
  ```

- **Video samples** for deck 06 live in `public/video/06/` (H.264 clips with `.jpg` posters) and
  `public/images/06/` (artefact crops, the explorer image). Clips are shown with
  `<VideoClip src="/video/06/…mp4" poster="/video/06/…jpg" caption="…" :width="205" />`: click to play, loops
  silently, starting one pauses the others; the PDF export shows the poster. Everything, together with the
  measured data behind deck 06's rate–quality, convex-hull and pooling figures
  (`scripts/data/06-video-metrics.json`, read by `generate-figures.py`), is produced by
  `scripts/generate-video-samples.py` from two SVT test sequences (Xiph.Org, no copyright). It downloads only
  the first 2 s of each into `~/.cache/qos-slides/` and needs ffmpeg with libx264, libx265, libsvtav1 and
  libvmaf (about 2 min):

  ```bash
  python3 scripts/generate-video-samples.py    # then: python3 scripts/generate-figures.py
  ```

- **Browser-only slides** (live animations) carry `class: export-skip` in their slide frontmatter; a rule in
  `style.css` hides them in the print view, so `npm run export` leaves the page out and the rest of the deck
  keeps its order. (Slidev 52's `--range` would be the obvious tool, but its print view ignores the range.)
  Deck 04's `GilbertSim` is the current example: a two-state loss "device" that shows every random draw and
  decides each packet's fate, a grid of transmitted/lost packets, and the cumulative loss against the model's
  steady state, with play/reset and sliders for the parameters and speed. `model` selects `bernoulli`,
  `simple` (default), `gilbert`, or `elliott`, e.g. `<GilbertSim model="elliott" :p="0.05" :q="0.3" :h="0.2" :k="0.97" />`.
  With `diagram` it draws only the state diagram (no current state, no animation, no controls), so the static
  model slides show exactly the drawing the live slides animate; it is plain SVG and prints in the PDF:
  `<GilbertSim model="gilbert" diagram alt="…" />`.
  Deck 06's `QualityExplorer` works the other way round: it stays in the export and draws a static layout
  there (Slidev's `isPrintMode`). Live, it shows six distortions of one grayscale image scaled to the same
  MSE (so equal PSNR), with SSIM, the SSIM map, a ranking table and an explanation per distortion; in the
  PDF, all six side by side at MSE 200 with their maps and one line of explanation each.
- **Units in prose** must be escaped, `\[Hz\]`, because MDC syntax treats `[...]` as a span. Inside `$…$` KaTeX
  they are fine as they are.
- **Math** — KaTeX, `$…$` inline and `$$…$$` blocks. The closing `$` may not be preceded by a space.
- **Code fences** — Shiki has no grammar for RouterOS or similar; an unknown language is a hard build failure.
  Use `bash` for shell-like config.
- **First paragraph after a title** is body text; `style.css` overrides the theme's dimmed "subtitle" treatment.

## Visual style

The decks follow the VŠB-TUO 2023 visual identity manual. The rules, the palette, and the reasoning behind the
places where the manual and screen accessibility disagree are in [VSB-STYLE.md](VSB-STYLE.md) — read it before
changing colours, fonts, or the logo.

Short version: university green `#00A499` is primary, FEI cyan `#05C3DE` is the accent and never used for text,
type is Carlito (the manual's Calibri substitute, metric-compatible and open source), and everything is
hard-edged — no rounded corners or shadows.

Fonts and logos are self-hosted in `public/`, so the built site and PDF export don't depend on what's installed on
the presenting machine.

## Pinning the Slidev version

`package.json` uses `latest` for `@slidev/cli`; `package-lock.json` pins what was last installed. Delete the lock
file and reinstall to move to a newer Slidev.
